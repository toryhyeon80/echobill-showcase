# 에코빌(EchoBill) 설계 북극성 (North Star)

> **정본(SSOT)** — Cursor · Claude Code · 팀 문서 공통.  
> **행동 강령·빌드:** [`CLAUDE.md`](../../CLAUDE.md) · **제품 범위:** [`SPEC_MASTER.md`](../../SPEC_MASTER.md) · **문서 충돌:** [`DOC_CRITERIA_ALIGNMENT.md`](../DOC_CRITERIA_ALIGNMENT.md)

logpick_core의 「완전 새 방식」을 **에코빌 7주 MVP에 맞게 재해석**한 문서다.  
범위·스택·API를 깨는 창작이 아니라, **현장 문제의 제1원리에서 더 단순한 경로를 고르는 것**이 목표다.

## 한 줄

> **"현장의 근본 진실에서 다시 쌓되, 기획 Must와 SPEC 계약은 깨지 마라."**

- **제1원리:** 유추(“장부 앱은 원래 이렇게”)로 멈추지 말고, 현장 진실로 분해한 뒤 다시 설계한다.  
- **가드레일:** 7주 MVP · 카톡 인앱 · LLM+Rule · 확인 전 미반영 · Mock 발행 등 **이미 확정된 축은 재협상 대상이 아니다.**

제1원리 (함축):

> *"Reason from first principles rather than by analogy… boil things down to the most fundamental truths… and then reason up from there."*  
> — Elon Musk

| | 의미 (에코빌) |
|---|---|
| **유추** | “캐시노트/장부대장처럼”, “네이티브 앱이 당연”, “LLM만 있으면 장부 확정 OK”, “웹훅 챗봇이 필수” |
| **제1원리** | 손은 없고 말은 있다 → **짧은 입력** → **구조화 후보** → **사장이 확인** → 그제야 장부·미수 |

## 근본 진실 (에코빌)

1. 현장에서는 **타이핑이 아니라 말**이 빠르다.  
2. AI는 틀린다 → **확인 없는 자동 확정은 금전 사고**다.  
3. 설치·회원가입은 **이탈**이다 → **이미 쓰는 카톡**이 입구다.  
4. 사장이 원하는 출구는 ERP 전체가 아니라 **외상·미수·(필요 시) 발행 상태**다.  
5. 7주는 짧다 → **Must를 닫고**, Stretch(95%·실팝빌·로컬 SLM)는 욕심이다.

이 다섯을 깨는 “참신한” 제안은 북극성이 아니라 **범위 일탈**이다.

## 에이전트 행동 원칙

설계·UX·파서 전략을 **새로 제안하기 전**에 한 번 멈춘다.

| 단계 | 질문 |
|---|---|
| **1. 근본** | 이번 변경이 위의 진실 중 무엇을 더 잘 지키나? |
| **2. 의심** | “업계 표준/템플릿/VoiceLedger 복사/무조건 Gemma 체이닝”만으로 채택하지 않았나? |
| **3. 재설계** | 같은 Must를 **더 단순·더 직접**하게 닫는 경로가 있나? (예: 챗봇 파싱 대신 인앱 한 화면) |
| **4. 가드레일** | SPEC 「하지 않는다」·기준 정리본 Critical과 **모순되지 않나?** |

**출력 규칙:** 아키텍처·UX·파서 **설계안**을 낼 때 가능하면 **"왜 유추가 아닌가"** 한 줄을 붙인다.  
**구현·버그픽스**는 [`CLAUDE.md`](../../CLAUDE.md) · 기존 코드 패턴 우선 (YAGNI). 매 커밋마다 철학 에세이 금지.

## 에코빌 적용 예

| 유추 (하지 말 것) | 제1원리 (우리 방식) |
|---|---|
| 스토어 앱이 신뢰다 | **카톡 링크 → 인앱 웹** (설치 허들 제거) |
| AI가 맞으면 바로 장부 | 항상 **`candidate` → 사용자 확정** |
| 챗봇으로 다 하자 | 채널은 **진입**, 작업은 **인앱 웹** (웹훅 파싱은 선택) |
| LLM만 / 룰만 | **LLM 메인 + Rule 폴백 + 확인 UI** (Champion·수동 폼) |
| 풀 ERP·실홈택스부터 | **FIFO 미수 + Mock 발행**으로 출구 검증 |
| 95% 아니면 배포 불가 | **80%·기능 Must** · 95%는 Stretch |
| VoiceLedger/LogPick 코드 이식 = 완성 | **계약(스키마·API)·원칙만** 이식, 스택·제품은 에코빌 |
| Admin으로 뭐든 고친다 | 사용자 삭제 UI 없음 · **CS 스크립트 + audit** |

## 판단 기준

- 제안이 “그냥 장부 SaaS”와 **구분되지 않으면** → 카톡·말·확인·미수 중 무엇을 더 날카롭게 할지 한 단계 더.  
- 복잡도 증가는 **근본 문제 해결**에 필요할 때만 (YAGNI).  
- **기획 Must / SPEC / DOC_CRITERIA_ALIGNMENT**와 모순되면 제1원리 제안이라도 **기각**하거나 D항으로 PM 결정.  
- “완전 새 제품”을 위해 7주 범위를 넓히지 않는다. 새로움은 **같은 Must 안의 더 단순한 경로**에서 나온다.
