## 2. 단계별 상세

### S0 코어 뼈대 — 10/7

| 결과물 | 담당 |
|---|---|
| STT 어댑터 `transcribe(audio, mime) → text` (Whisper). 원본 오디오는 STT 직후 삭제, 복구 실패는 504 (CLAUDE.md §4-3·10, DL-16 어댑터 전제) | PM (리뷰 수경) |
| `/parse`에 LLM 파서 연결 — 5초 초과·실패 → Rule 폴백(그날 있는 수준), Rule 성공은 200 | PM (리뷰 수경) |
| BE 머지: #20 후보 저장·검증 → #18 카카오 로그인 → #13 채점·LLM 파서 → #21 확정 → #22 미수 | PM 리뷰, 병철 지적 반영(10/5~) |
| 터미널 시연 스크립트 (녹음 파일 → 후보 JSON → 400 보완 → (되면) 확정 → 장부) | PM |
| 성능표 v0: 개선 전(9/29) → + 한글 수사 정규화 → + 프롬프트·후처리, Dev 60건 × 3회 | 수경 (10/6 저녁) |

- **되면(목표선):** 확정 → 장부 반영, 화면에서 녹음부터 확정까지.
- 10/7 이후 프롬프트 고정은 **판정식 A 비교용 기준선**에만 해당한다. 개선은 S4까지 계속한다.

### S1 기준선·비교 — 10/8~10/11

- 10/8: Rule 60건 기준선 + 판정식 A ([D02](D02_판정식.md) §3). 전제: Rule 파서 본체(10/5~10/7), 한글 숫자 변환기.
- 10/8 전: `validation.py`를 채점기에 연결해 추가 확인 적합성 측정.
- 10/9: 판정식 B 비용 승인(PM). 후보 모델 연동이 막히면 그날 보고 → 4주차로 조정.
- 10/10~11: 판정식 B (mini vs 후보 1개, DL-11 "1회만"). 결과는 중간 보고서 재료.

### S2 인앱 시연 빌드 — 10/14

- 카톡 인앱 실기기(Android·iPhone)에서 텍스트 입력 → 후보 → 수정 → 확정 (SPEC §9.2 4주차).
- 운영 배포: Railway(PM 계정, DL-17) + Cloudflare Pages(GitHub 자동 배포). 첫 배포 스모크 [deploy.md §8](deploy.md) — `dev-token` 404, 쿠키 속성.
- 운영 DB 마이그레이션 방법 확정 (병철, [deploy.md §6](deploy.md)).

### S3 음성 E2E·STT 비교 — 10/21

- 인앱 녹음 → 업로드 → STT → 후보 → 확정. 녹음 형식은 Android·iPhone 모두 `audio/webm;codecs=opus` 확인 완료(10/1).
- STT 비교 1회: Whisper vs CLOVA Speech 또는 리턴제로 중 1개 (DL-16). 비교 셋은 팀원이 녹음한 **Dev Golden 20~30건**(최종 평가용 문장은 녹음 금지). 지표는 WER가 아니라 **STT → 파서 결과**의 금액 Exact·필수 필드 + STT 지연 p95·비용.
- 사용성 테스트 모집 주초 시작 (D11).

### S4 개선 — 10/28

- Seed(팀원 문장 + 인터뷰에서 모은 실제 고객 표현)와 사용자 수정 피드백으로 개선 → **개선 전후 비교 최소 1회** (기획서 §6.3).
- Champion 판정: 거래 전체 정확도 80% 미만이면 Rule 전환, 둘 다 미만이면 수동 모드 (기획서 §6.5). **95%는 Stretch** — 배포 게이트 아님.
- 적용 모델 고정 (기획서 6주차 게이트).

### S5 동결·최종 평가 — 10/30 → 11/2

- 10/30 개발 동결 후 파서·프롬프트·검증 규칙 변경 금지 (DL-18).
- 11/1~2: **PM이 직접** 최종 평가용 40건을 1회 채점, 동결 커밋 해시 기록 (DL-25). 이 셋은 그 전까지 튜닝·판단에 쓰지 않는다.

## 3. 단계마다 보고하는 숫자 (같은 표 양식)

| 지표 | 기준 문서 |
|---|---|
| 거래 전체 정확도 · 금액 Exact · 필수 필드 F1 · 추가 확인 적합성 | [SCORING.md](../data/golden/SCORING.md), D03 |
| LLM 지연 p95 · 5초 초과 비율 | [D02](D02_판정식.md) §4 |
| **건당 비용** (STT + LLM, 토큰 기준 추정) — 사업성 검증 자료 (9/30 멘토링) | 채점 실행기 토큰 기록 |
| 3회 반복 편차 | D02 §1-4 |

- 데이터: 판단·튜닝은 **Dev Golden 60건**만. Seed 점수는 참고값.
- 숫자는 항상 "Dev 60건 기준"이라고 밝힌다. 최종 성능은 S5에서만 말한다.
