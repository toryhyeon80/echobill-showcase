# 에코빌 정확도 개선 — 팀원별 역할 및 협업 사항

## 목표

개발용 Golden 60건에서 GPT-4o-mini와 Rule의 정확도·안정성을 측정하고, 한글 금액·수량·선택 필드 오류를 줄인다. 최종 판단은 PM 검수 완료 Golden과 같은 채점 기준의 전후 측정 결과로 한다.

## 역할

| 담당 | 책임 | 이번 산출물 |
|---|---|---|
| 최승현 PM | Golden 정답·난이도·오류 코드 최종 검수, API·정책 승인, PR 리뷰와 main 머지 | 신규 20건 검수 결과, 확정 정책, 리뷰 의견 |
| 김수경 AI·데이터 | 프롬프트·Rule 개선, 채점·기준선 실행, 오류 분석, 개발용 Golden 관리 | 개선 전후 보고서, 오답 분석표, Rule 기준선, 채점 코드 |
| 최병철 백엔드 | 공통 검증 모듈과 오류 응답, LLM·Rule 전환 연결, 후보 재검증 | `validation.py`, 400 응답, API·검증 테스트 |
| 이예령 프론트엔드 | 오류 필드 표시, 후보 수정·재제출, 대기·실패 안내 | 확인 화면 연동, 수정 재제출 흐름 |

## 확정된 협업 경계

- AI는 발화에서 후보 JSON을 추출한다.
- 백엔드는 후보의 필수값·산술·범위·품목 수를 검증하고 오류 코드와 `problem_fields`를 결정한다.
- 프론트엔드는 백엔드가 반환한 필드를 강조하고 사용자가 수정한 후보를 다시 보낸다.
- PM은 Golden 정답·채점 기준·정책·main 반영을 결정한다.

추가 확인 적합성은 AI 후보만으로 판정하지 않는다. 백엔드 공통 검증 모듈의 실제 400 응답을 채점기에 넣어 측정한다.

## 이번 주 우선순위

| 순서 | 담당 | 작업 | 완료 기준 |
|---:|---|---|---|
| 1 | PM | 신규 20건 041~060 검수 | `review_status: 검수 완료` 또는 재검토 사유 기록 |
| 2 | AI | 한글 금액 오류 분석 및 프롬프트 개선안 작성 | 일반 규칙으로 작성, Golden 문장 복사 금지 |
| 3 | BE | 공통 검증 모듈 구현 | D03 오류 코드·필드·우선순위 테스트 통과 |
| 4 | FE | 오류 응답 화면 연결 | `problem_fields` 강조와 수정 재제출 확인 |
| 5 | AI | 60건 기준선 및 개선 후 재측정 | 원시 예측·요약·보고서 보존 |
| 6 | AI·BE | Rule 기준선 및 추가 확인 적합성 측정 | 같은 Golden·같은 검증 응답으로 비교 |
| 7 | PM | 비교 결과 검토 | 다음 프롬프트·Rule·운영 정책 결정 |

## PM 검토 요청

1. 신규 20건의 원문, 정답, 난이도 4조건, `expected_error_code`, `problem_fields`
2. 동명 품목 사례 052·053의 정답 행 분리와 수량 최적 대응 검증
3. 한글 금액 오류 분석 1차 5건의 정답 근거와 프롬프트 개선 방향
4. 개선 전후 60건 결과가 나온 뒤, LLM과 Rule 중 운영 경로 판단

D03 §0.2에서 확정된 품목 매칭, 키 누락, 선택 필드, 오류 우선순위는 재결정 대상이 아니다. 구현이 규칙을 충족하는지 검토한다.
