> 상태: **v0.1** (2026-10-08, PM 확정 — 결제 완료 색은 10/9까지 최종 확인) · 화면 프롬프트 전문은 노션(SSOT), 이 문서는 **토큰·컴포넌트·문구 기준**

> 코드 반영: Tailwind 설정의 색·크기는 **이 문서의 토큰 이름과 값을 그대로** 쓴다. 값을 바꿀 땐 이 문서와 Tailwind 설정을 같은 PR에서 바꾼다.

## 0. 원칙

1. **고령 사용자(50대 이상) 기준** — 큰 글씨, 고대비, 넉넉한 여백, 터치 영역 48px 이상
2. **한 화면 한 동작** — 화면마다 주 버튼은 하나
3. **확인은 사용자가** — AI 결과는 "후보"로 보여 주고, 확정은 사용자가 누른다
4. **모르면 묻기** — 한 번에 한 칸만, 버튼으로 끝낼 수 있게 (DL-31)
5. **카톡 인앱 우선** — `100dvh`, Safe Area, 하단 버튼이 카톡 바에 가리지 않게
6. 라이트 모드만. 장식 그림·그림자 최소, 선보다 면으로 구분

## 1. 색 (토큰)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `brand` | `#3182F6` | 주 버튼, 선택 상태, 링크 강조 |

| `action-neutral` | `#F3F3F3` | 처음 사용 [없어요]·되묻기 [원문으로 돌아가기] 바탕, `text` 글씨, 테두리 없음 |
| `text-strong` | `#191F28` | 제목, 금액 |
| `text` | `#333D4B` | 본문 |
| `text-sub` | `#4E5968` | 설명 |
| `text-weak` | `#8B95A1` | 보조 문구, 비활성 글자 |
| `bg` | `#F2F4F6` | 회색 바탕(선택 칸·입력 칸·수정 창 품목 묶음). 화면 바탕은 확인·로그인 화면처럼 흰색(`surface`)이 기본 — 섹션과 섹션 사이는 **전체 폭 12px 회색(`bg`) 띠**로 나누고 테두리 선은 쓰지 않는다. 화면의 핵심 카드 하나(확인 화면 요약 카드)만 **그림자**(`shadow-card`: 0 4px 24px 8% + 0 1px 3px 4%, 모서리 24px)로 띄운다 (10/8 PM) |
| `surface` | `#FFFFFF` | 카드, 시트 |
| `line` | `#E5E8EB` | 구분선(필요할 때만) |
| `line-strong` | `#D1D6DB` | 흰 바탕 위 상자 테두리(문서 목차, 10/12 PM) |
| `unpaid` | `#E8590C` | **미수금** 점·선택 테두리·큰 금액 (주황, 10/8 v0 비교 후 변경) |
| `unpaid-text` | `#C2410C` | 미수금 작은 글자(배지·선택 칸 글자 — 흰/연주황 바탕에서 읽히는 진한 주황) |
| `unpaid-soft` | `#FFF3E6` | 미수금 배지·선택 칸 바탕 |
| `paid` | `#12A150` | **결제 완료** 글자·점·배지 (초록, 10/8 임시 확정 — v0 결과 보고 10/9까지 최종) |
| `paid-soft` | `#E8F7EE` | 결제 완료 배지 바탕 |
| `danger` | `#F04452` | 오류 안내·입력 칸 오류 테두리·위험 동작(후보 버리기·로그아웃 확인) |
| `danger-soft` | `#FFEEEE` | 오류 안내 바탕 |

- **색은 꼭 필요할 때만 (10/9 PM).** 화면 대부분은 검정·회색·흰색이고, 색은 아래 네 가지 뜻에만 쓴다. 새 뜻이 필요해도 색을 늘리지 말고 글자·아이콘으로 구분한다
  - 파랑 `brand` = 누르는 것·선택된 것 (주 버튼, 선택 표시, 링크)
  - 주황 `unpaid` = 받을 돈(미수금)
  - 초록 `paid` = 결제 완료
  - 빨강 `danger` = 오류·위험 동작
  - 금액은 기본 검정. 받을 돈일 때만 주황. 경고용 노랑(`warning`)은 쓰지 않아 토큰에서 뺐다
- 의미 색은 고정: **미수금 = 주황, 결제 완료 = 초록, 오류 = 빨강**. 미수금은 「잘못」이 아니라 「받을 돈」이라 오류 빨강과 나눈다. 브랜드 파랑과 섞지 않는다.
- 예외: **카카오 로그인 버튼**은 카카오 공식 디자인(`#FEE500` 바탕, 검은 말풍선, 글자 `rgba(0,0,0,0.85)`)을 따른다. 최종 적용은 Kakao Developers 공식 버튼 가이드·리소스로.

## 2. 글꼴·글씨 크기

- 글꼴: **Pretendard** (없으면 system-ui)
- 최소 글씨 15px. 본문은 18px 이상

| 토큰 | 크기 / 줄 높이 / 굵기 | 쓰는 곳 |
|---|---|---|
| `display` | 40 / 48 / Bold | 확인 화면 총액, 로그인 문구, 입금 금액 |
| `title` | 24 / 32 / Bold | 화면 제목, 질문 카드 질문 |
| `subtitle` | 20 / 28 / SemiBold | 거래처 이름, 섹션 제목 |
| `body` | 18 / 26 / Regular·Medium | 본문, 목록 |
| `button` | 18 / 24 / SemiBold | 버튼 |
| `caption` | 15 / 22 / Regular | 보조 설명, 링크 |

- 금액은 천 단위 쉼표 + "원" (예: `45,000원`), 숫자는 고정폭 숫자(tabular-nums)
- **줄바꿈은 낱말 단위**(10/12 PM): 글자 중간에서 끊지 않는다("말해 보/세요" ✗ → "말해/보세요"). 전체 기본값 `word-break: keep-all`, 긴 주소만 예외로 끊김
- 확인 화면 "말씀하신 내용"은 라벨을 한 줄로 따로 두고, 사장님 문장은 **쉼표 단위로 묶어** 줄이 바뀌면 쉼표 뒤에서 바뀌게 한다("…사만오천 원, / 무 두 개 사천 원")

## 3. 여백·모서리·높이

| 항목 | 값 |
|---|---|
| 화면 좌우 여백 | 20px (작은 화면 320px에서도 유지) |
| 공통 헤더 | 콘텐츠 행 48px + 위쪽 safe area, 좌우 20px. 오른쪽 버튼 유무와 무관하게 고정 |
| 간격 토큰 (10/15 전달 반영) | page=20px, header=48px, space-1~8=4/8/12/16/20/24/28/32px. Tailwind px-page·gap-space-4 등으로 공유 |
| 카드 안 여백 | 20–24px |
| 요소 사이 | 8 / 12 / 16 / 24 / 32 (4의 배수) |
| 모서리 | 버튼·입력칸 12px, 카드 16px, 바텀시트 위쪽 24px |
| 버튼 높이 | 주·보조 56px, 작은 버튼 48px |
| 하단 고정 버튼 영역 | 버튼 + 위아래 12px + `env(safe-area-inset-bottom)` |
| 하단 탭 | 높이 64px + safe area, 본문 하단 여백을 탭·FAB 높이만큼 |

헤더는 `ui/AppHeader`를 공통으로 사용한다. 하단 탭으로 오가는 세 화면(기록·장부·세금계산서)은 헤더 오른쪽에 같은 마이페이지 버튼(`MyPageButton`, 사람 아이콘)을 두고, 마이페이지의 `‹`는 들어온 탭으로 돌아간다(10/19 PM). 앱과 `/design`은 모두 문단 기본 margin을 초기화하고 명시적 간격 토큰을 사용한다. 기록 홈의 녹음 패널은 확인 화면 버튼 패널과 같은 모양·높이(위 16px, 예시 한 줄, 버튼 56px, 아래 12px)로 하단 탭 바로 위에 붙인다(10/19 PM). `/design?compare=1&screen=home`은 개발용 선택 도구를 숨겨 같은 뷰포트로 연결 화면과 비교할 수 있다.

## 4. 버튼 체계

| 종류 | 모양 | 쓰는 곳 | 규칙 |
|---|---|---|---|
| **주 버튼** | `brand` 꽉 찬 바탕, 흰 글자, 56px, 너비 꽉 참 | 장부 확정, 후보 만들기, 입금, 제출 | **화면당 하나** |
| **보조 버튼** | `brand-soft` 바탕, `brand` 글자, 56px | 수정, 다시 말하기 | 주 버튼과 나란히 둘 때 30% : 70% (보조 : 주). 확인 화면 보조 버튼 글자는 **"내용 수정"** (10/8 v0 비교 후 변경 — 30% 칸에 들어가고 "수정"보다 분명) |
| **텍스트 링크** | 밑줄 또는 색 글자, 15–16px | 개인정보 처리방침 (다른 페이지로 가는 것만) | 화면 안 동작에는 쓰지 않고 작은 버튼을 쓴다 (10/8 PM). 예외: 마이페이지 [탈퇴 요청]은 일부러 회색 밑줄 글자 (10/9 PM) |
| **작은 버튼** (10/8 PM) | 알약 모양 48px, `bg` 회색 바탕 + `text-strong` 글자 + 앞에 아이콘 | 다른 내용도 고치기(✏️), 글자로 입력하기(⌨️) | 글자만 있는 링크는 버튼으로 안 보여서 쓰지 않는다 (링크는 "개인정보 처리방침"처럼 다른 페이지로 가는 것만) |
| **위험 동작** | 작은 버튼 모양, `danger-soft` 바탕 + `danger` 글자 + 🗑 아이콘 (10/8 PM) | 후보 버리기 확인, 로그아웃 확인 | 반드시 확인 창(취소 / 버리기) |
| **선택 버튼(2지선다)** | 큰 칸 두 개, 선택 시 테두리·바탕 강조 | [미수금] [결제 완료] | 처음엔 둘 다 선택 안 됨 |
| **아이콘 버튼** | 아이콘 24px, 터치 영역 48px | 닫기(×), 뒤로(‹), 마이크 | `aria-label` 필수 |

- **닫기(×)**: 화면·시트 오른쪽 위, **화면에 하나만**
- **뒤로**: 왼쪽 위 `‹` 아이콘 + 글자(예: "‹ 거래 입력"). 고령 사용자를 위해 아이콘만 쓰지 않는다
- **홈** (10/19 PM): 오른쪽 위 집 아이콘(`HomeIcon` — 처마가 벽 밖으로 나온 지붕 + 벽, 문 없음), 터치 영역 48px, 화면 읽기 이름 "기록 홈으로". **하단 탭이 없고 `‹`를 여러 번 눌러야 홈에 가는 화면에만** 둔다(이미 있는 외상 옮기기 등 여러 단계 화면). 하단 탭이 있거나 `‹` 한 번이 곧 홈인 화면(기록 확인, 마이페이지, 입금 등록)에는 두지 않는다 — 같은 동작 버튼을 늘리지 않는다. 오류 화면의 [기록 화면으로]도 같은 아이콘
- 상태
  - 누름: 주 버튼 `brand-pressed`, 그 외 약간 어둡게
  - 비활성: 바탕 `line`, 글자 `text-weak` (투명도만 낮추지 않음)
  - 로딩: 글자 옆 스피너 + "…하는 중", 다시 누르기 막기(중복 요청 방지)

## 5. 공통 컴포넌트

### 5-1. 하단 고정 버튼 영역 (Bottom CTA)
- 흰 바탕, 위쪽 구분은 그림자 대신 `line` 1px 또는 그라데이션
- 카톡 하단 바·키보드에 가리지 않게 safe area + 포커스 시 `scrollIntoView({ block: "center" })`

### 5-2. 바텀시트
- 화면 위를 덮는 레이어, 배경 어둡게(검정 80% — 10/9 PM. 확인 창도 같음), 위쪽 모서리 24px, 손잡이 막대
- 쓰는 곳: **내용 수정하기**(확인 화면), 입금, 되묻기 질문 카드
- 닫기: × 또는 바깥 누름(작성 중이면 "작성 중인 내용이 있어요" 확인)

### 5-3. 되묻기 질문 카드 (DL-31)
- 바텀시트 안에 **한 번에 한 칸**만: 큰 질문(`title`) + 🎤 말로 답하기 + 버튼·키패드
- 음성으로 입력했다면 위에 "이렇게 들렸어요: …"(`caption`, `text-sub`)
- 칸별 대체 입력: 외상 → [미수금] [결제 완료], 수량·총액 → 숫자 키패드(총액은 들린 금액 후보 버튼), 거래처 → 최근 거래처 버튼 + 직접 입력
- 질문은 카드가 뜰 때 **자동으로 읽어 줌**(서버 음성, DL-31 10/26). 스피커 아이콘 = 다시 듣기, 소리 끄기는 따로. 음성 답이 꺼진 칸은 🎤 숨김
- 아래 텍스트 버튼 "다른 내용도 고치기" → 전체 수정 시트
- 하단(10/29 PM): [원문으로 돌아가기] `action-neutral` + [다음 질문 / 입력 내용 확인하기] `brand`를 한 줄 1:2, 간격 8px, 높이 56px로 배치. 고를 항목이 없으면 안내는 "직접 입력해 주세요". 음성 답 실패 시에도 서버가 돌려준 들린 말을 표시한다.

### 5-4. 확인 창 (Dialog)
- 가운데 카드, 제목 `subtitle` + 설명 `body`, 버튼 두 개(취소 = 보조, 실행 = 주 또는 위험)

### 5-5. 토스트
- 화면 아래(하단 탭 위), 2–3초, 짧은 한 줄("장부에 저장했어요")
- 오류는 토스트로 끝내지 않고 화면 안내로

### 5-6. 하단 탭
- **3개** (SPEC §4): **기록**(`/record`, 마이크 아이콘) / **장부**(`/ledger`, 책 아이콘) / **세금계산서**(`/tax-invoice`, 영수증 아이콘)
- 세금 화면이 준비되기 전에는 설정으로 세금 탭만 숨길 수 있게 한다 (디자인은 3개 기준)
- **확인 화면은 하단 탭 위에 버튼 패널을 얹는다** (10/8 PM, 삼성증권 앱 방식): [내용 수정][장부 확정] 패널은 위쪽 모서리 24px + 위로 퍼지는 옅은 그림자, 그 아래 하단 탭. 둘이 한 묶음으로 화면 아래에 고정
- 선택 탭: `brand` 아이콘·글자, 나머지 `text-weak`. **글자 15px 이상**(12px `text-xs` 금지), 아이콘 24px

### 5-7. 배지
- 확인 화면 상단 상태: "내용 확인 · 장부 미확정" (`brand-soft` 바탕, `brand` 글자)
- 미수금: `unpaid-soft` 바탕 + `unpaid-text` 글자 / 결제 완료: `paid-soft` 바탕 + `paid` 글자

### 5-8. 빈 화면·불러오는 중
- 빈 화면: 짧은 안내 + 다음 동작 버튼(예: "아직 기록이 없어요" + [말로 기록하기])
- 불러오는 중: 목록·카드는 스켈레톤(회색 막대 — 실제 내용과 같은 크기, 받을 돈 금액·목록 줄 모양, 움직임 줄이기면 멈춤, `Skeleton`·`SkeletonRows`. 불러오는 동안 [+ 입금] 숨김), 화면 전체·처리 대기는 **점 세 개 삼각형 회전**(`DotsSpinner` — 큰 것은 `brand`, 버튼 안은 글자색, 1.2초에 한 바퀴, 움직임 줄이기 설정이면 멈춤). 3초 넘으면 "조금만 기다려 주세요" (자리는 처음부터 비워 둬 위치가 튀지 않게)
- 로고가 생기면 앱 시작 화면만 로고로 바꾼다 (토스 방식). 그 전에는 점 세 개

### 5-10. 토글 (10/8 PM)
- 한 줄: 왼쪽 라벨(`body` 굵게) + 회색 설명, 오른쪽 52×32 스위치(켜짐 `brand`, 꺼짐 `line`). 동의처럼 기본값은 꺼짐
- 공용 컴포넌트: `Toggle`

### 5-11. 완료 알림 (토스트, 10/9 PM)
- 화면 아래(하단 탭·버튼 패널 위)에 뜨는 **검정 알약**: 체크 + 한 문장, 약 2.5초 뒤 사라짐(동작 버튼이 있으면 조금 더). 색 없음(검정·흰색만)
- 문구: "장부에 저장했어요 [장부 보기]" · "{거래처}에서 N원 입금을 등록했어요" · "모의 발행을 마쳤어요" · "사업자 정보를 저장했어요"
- 오류는 토스트로 알리지 않는다 (오류 화면·칸 아래 빨강 안내). 공용 컴포넌트: `Toast`, `useToast`

### 5-12. 작성 중 나가기 확인 (10/9 PM)
- 내용이 있는 기록·확인 화면에서 **뒤로가기**를 누를 때만: "작성 중인 장부가 있어요 / 나가도 내용은 이 기기에 남아 있어서, 기록 화면에서 이어서 확인할 수 있어요" + [계속 확인][나가기]
- 위험 동작이 아니라 빨강 아님(초안은 남는다). 카톡 웹뷰 닫기(X)는 막지 않는다 — 복구로 대응(CLAUDE.md 호환 가드 3). 공용 컴포넌트: `LeaveDraftDialog`

### 5-9. 입력 칸 (10/8 PM, 토스 방식)
- **상자 없이 밑줄**: 위에 작은 회색 라벨(`caption`), 값은 크게(`subtitle` 20px), 아래 2px 회색 밑줄(`line`). 입력 중이면 밑줄 `brand`, 오류면 밑줄·라벨 `danger` + 밑줄 아래 안내 한 줄("수량을 확인해 주세요")
- 금액은 입력하는 동안 **쉼표**(45,000)를 붙이고 뒤에 "원". 수량은 소수점 허용(2.5), 뒤에 단위
- 칸 사이 간격 24px, 묶음(품목) 사이 32px. 묶음을 회색 상자로 감싸지 않는다
- 여러 줄 글 입력(홈 "글자로 입력하기")만 회색 바탕 상자 + 입력 중 `brand` 테두리
- 공용 컴포넌트: `UnderlineField`

## 6. 화면 문구 (용어)

| 쓰는 말 | 쓰지 않는 말 |
|---|---|
| **미수금** / **결제 완료** | 외상(화면 표시), credit, 현금(상태 표시로) |
| 장부 확정 | 저장, 등록 |
| 후보 | AI 결과, 추론 |
| 내용 수정 | 편집 |
| 이 후보 버리기 | 삭제, 거절 |

- 말투: 해요체, 짧게("외상이에요, 현금이에요?", "장부에 저장했어요")

- 세금 화면은 "모의 발행"임을 항상 표시, 실제 국세청 전송처럼 보이는 표현 금지 (CLAUDE.md §4-5)

## 7. 접근성

- 터치 영역 48px 이상, 글자 대비 4.5:1 이상
- 아이콘 버튼 `aria-label`, 포커스 표시 보이게
- 자동으로 넘어가는 슬라이드·애니메이션 금지, 움직임은 짧게(200ms 이하)
