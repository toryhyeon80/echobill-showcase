## 1. 공통 측정 조건

1. **데이터:** PM 검수 완료된 개발용 Golden만 사용한다. 60건 전체가 검수 완료되기 전에는 판정하지 않는다.
2. **분모:** 거래 전체 정확도는 `정상 구조화 가능` 사례(현재 v2.5 기준 42건), 금액 Exact는 정답 총액이 있는 전체 사례, 필수 F1은 SCORING.md §1을 따른다.
3. **같은 조건:** 같은 Golden 파일(sha256), 같은 채점기(sha256), 같은 JSON 스키마, temperature 0. 모델 비교 시 같은 프롬프트.
4. **반복:** LLM은 3회 실행한다. 거래 전체 정확도가 중앙값인 실행을 **대표 실행**으로 삼고, 모든 지표를 그 실행에서 읽는다. 중앙값과 거래 전체 정확도가 같은 실행이 여럿이면 **먼저 실행한 것**을 대표 실행으로 한다. Rule은 결정적이므로 1회.
5. **대응 비교:** 같은 레코드끼리 비교한다. `LLM만 정답 b건`, `Rule만 정답 c건`을 함께 보고한다. 차이 Δ = b − c.
6. **보존:** 원시 예측·요약·보고서를 모두 `eval/results/`에 남긴다. 예측 행마다 전송 원문 해시(`sent_text_sha256`)를 기록한다.
7. **지연 측정 조건:** 두 모델의 지연은 같은 시간대·같은 네트워크에서 **번갈아** 측정한다 (mini 1회차 → 후보 1회차 → mini 2회차 → …). 한 모델을 몰아서 돌리면 시간대별 서버 부하 차이가 모델 차이로 섞인다. 현재 `eval/run_baseline.py --repeat`는 한 모델의 반복만 연달아 실행하므로, 후보 모델 파서를 추가하는 3주차 비교 작업에서 두 모델을 번갈아 실행하는 기능을 함께 만든다. 그 전에는 모델 비교 판정을 하지 않는다.

## 2. 지표별 3단 판정

지표마다 비교 대상 대비 **우위 / 동등 / 열위**를 판정한다.

| 지표 | 단위 | 허용 폭 m |
|---|---|---|
| 거래 전체 정확도 | 건수 | max(**2건**, 반복 편차) |
| 금액 Exact | 건수 | max(**2건**, 반복 편차) |
| 필수 필드 micro F1 | %p | max(**2.0%p**, 반복 편차) |

- 반복 편차 = 3회 실행의 최댓값 − 최솟값. 두 모델을 비교할 때는 둘 중 큰 값을 쓴다.
- Δ ≥ m → 우위, Δ ≤ −m → 열위, 그 사이 → 동등.
- 2건은 42건 기준 약 4.8%p로, DL-11 예시의 "+2건(5%p)"과 같은 크기다.

**해석 제한:** 42건에서 2건 차이는 통계적으로 유의하지 않다. 예를 들어 b=3, c=1이면 정확 McNemar 검정 p≈0.63이다. 이 판정식은 **운영 경로를 고르는 규칙**이며 모델 우열을 증명하는 검정이 아니다. 보고서에는 b·c와 McNemar p를 참고값으로 함께 적는다.

## 3. 판정식 A — LLM 대 Rule

### 3.1 종합 판정

| 금액 Exact | 필수 F1 | 판정 |
|:-:|:-:|---|
| 우위 | 우위·동등 | **LLM 우위** |
| 동등 | 우위 | **LLM 우위** |
| 동등 | 동등 | **동등** |
| 열위 | (무관) | **LLM 열위** |
| 동등 | 열위 | **LLM 열위** |
| 우위 | 열위 | **엇갈림** → 거래 전체 정확도의 3단 판정을 그대로 따름 |

**금액 열위를 먼저 보는 이유:** 한글 금액 오답 분석(1차 5건)에서 g-dev-008은 수량 × 단가 = 품목 금액 = 총액이 모두 맞는데도 원문 금액과 달랐다. 이런 금액 오류는 산술 검증을 통과해 확인 화면에서 사용자가 놓치기 쉽다. 거래처·품목명 오류는 화면에서 눈에 잘 띈다.

**엇갈림을 거래 전체 정확도로 푸는 이유:** 거래 전체 정확도는 금액과 나머지 필수 필드를 모두 포함하고, 80% 기준에 이미 쓰는 지표다.

### 3.2 운영 조치

| 판정 | LLM 운영 중 | Rule 운영 중 |
|---|---|---|
| LLM 우위 | LLM 유지 | 복귀 조건 중 "Rule 대비 우위" 충족. 80%·PM 승인은 별도 |
| 동등 | LLM 유지 (열위가 아님) | 복귀하지 않음 (우위가 아님) |
| LLM 열위 | 전체 자동 파싱을 Rule로 전환 | Rule 유지 |

동등 구간에서는 현재 경로를 바꾸지 않는다. 비슷한 수치에서 LLM과 Rule이 번갈아 전환되는 것을 막는다.

### 3.3 추가 확인 적합성 (측정 가능해진 뒤)

- 기획서 §6.5의 전환 조건은 금액 Exact·필수 F1이다. 따라서 추가 확인 적합성은 Rule **전환** 조건에 넣지 않는다.
- 다만 LLM 적합성이 Rule보다 열위이면 "LLM 우위"를 "동등"으로 낮춘다. 복귀 근거로 쓰지 않는다는 뜻이다.
- 적합성은 백엔드 공통 검증 모듈의 실제 400 응답으로 측정한다 (SCORING.md §1).

## 4. 판정식 B — GPT-4o-mini 대 후보 모델 (DL-11)

순서대로 적용하고, 앞 단계에서 결론이 나면 멈춘다.

1. **자격:** 후보가 거래 전체 정확도 80% 이상이고 판정식 A로 Rule 대비 "LLM 우위"여야 한다. 아니면 **교체 안 함**.
2. **거부 조건:** 다음 중 하나라도 해당하면 **교체 안 함**.
   - mini 대비 금액 Exact 열위
   - mini 대비 추가 확인 적합성 열위 (측정 가능한 경우)
   - 후보의 호출 지연 p95 > **4,000ms**. 5초 제한에 가까워 운영 중 Rule 폴백이 잦아진다.
   - 후보의 **5초 초과 비율 > 5%** (실패 포함 전체 호출 시간 기준, 대표 실행). p95는 성공 호출만으로 계산하므로 5초를 넘겨 끊긴 호출이 빠져 느린 모델이 좋아 보일 수 있다.
   - mini 대비 **외상 잘못 확정**이 많음 (DL-27 보고 지표, CI 회귀 검사와 같은 기준)
3. **정확도:** mini 대비 거래 전체 정확도가 우위면 **교체**, 열위면 **교체 안 함**.
4. **동등일 때:** 기본은 **mini 유지**다 (연동·검증 이력 보존). 아래 조건이면 교체를 PM에 제안한다.
   - p95가 mini보다 **20% 이상** 빠르고 추정 비용이 mini의 **1.5배 이하**, 또는
   - 추정 비용이 mini보다 **50% 이상** 낮고 p95가 mini보다 **10% 넘게** 느리지 않음

지연은 성공 호출 기준 p95와 5초 초과 비율(`measurements.over_deadline`, 묶음별 `group.json`의 `over_deadline_rate`)을 함께 쓴다. 비용은 성공 응답 토큰 기준 추정치다.

## 5. 적용 예시 (가상 수치)

> 아래는 판정식 작동을 보이기 위한 **가상 수치**다. 실제 측정 결과가 아니다.

| 지표 | LLM 대표 실행 | Rule | Δ | m | 지표 판정 |
|---|---:|---:|---:|---:|:-:|
| 거래 전체 정확도 (42건) | 36 | 34 | +2 | 2 | 우위 |
| 금액 Exact (56건) | 46 | 49 | −3 | 2 | 열위 |
| 필수 F1 | 93.1% | 89.0% | +4.1%p | 2.0%p | 우위 |

금액 Exact가 열위이므로 3.1에 따라 **LLM 열위**다. F1과 거래 전체 정확도가 우위여도 결론이 바뀌지 않는다. LLM 운영 중이라면 Rule로 전환한다.

## 6. 현재 기준선에 대한 참고

현재 GPT-4o-mini 기준선(`gpt-4o-mini-20260929-105945-kst`)은 개선 전 프롬프트로 기존 40건만 측정한 잠정 결과다. 거래 전체 정확도는 11/28 = 39.29%이고 Rule은 아직 비교할 수 없는 mock이다. 따라서 이 결과로 판정식을 적용하지 않는다. 첫 공식 적용은 60건 검수 완료, 프롬프트·금액 변환 개선, Rule 기준선 측정이 끝난 뒤다.
