# 채점 스크립트 `eval/`과 GPT-4o-mini 기준선 측정 공유

## 현재 상태

채점 규칙은 `data/D03_D04_결정안.md` §0.2의 2026-09-29 확정 내용을 반영했다. 개발용 Golden은 60건(v2.5)이며, 60건 전부 PM 검수 완료 상태다 (001-040: 2026-09-28, 041-060: 2026-09-29, PR #9). 신규 20건은 v2.4 초안을 v2.5에서 재작성했으므로 v2.4 기준의 신규 20건 결과는 쓰지 않는다.

GPT-4o-mini를 실제 호출한 기준선은 기존 40건 1회뿐이다. 신규 20건과 확정 채점 규칙으로 60건을 다시 호출한 결과는 아직 없다. 따라서 아래 수치는 **40건 기준선**이며 60건 성능 또는 개선 후 성능으로 해석하지 않는다.

## 확정 규칙 반영 사항

| 항목 | 현재 처리 |
|---|---|
| 거래처·품목명 | 모든 공백 제거 후 완전 일치, 공백 때문에 통과한 건수 별도 보고 |
| 수량 | Decimal 수치 비교. `5`와 `5.0`은 같고 `null`·`0`은 다름 |
| 동명 품목 | 이름 일치 항목 중 수량 일치 수가 최대가 되도록 1:1 대응 |
| 이름 불일치 품목 | 정답 `name`·`qty`는 FN, 예측 `name`·`qty`는 FP |
| 선택 필드 | 잘못 생성은 FP, 정답 값 누락은 `optional_field_missing`으로 분리 |
| 키 누락 | `null`로 간주. 숫자 문자열·`credit: 0/1` 등은 자료형 오류로 별도 기록 |
| 추가 확인 적합성 | HTTP 400, 기대 오류 코드, `problem_fields`, 근거 없는 값 생성 여부를 모두 확인 |

기존 40건 원시 예측을 현재 채점기로 다시 계산하면 거래 정확도·금액 Exact·필수 F1은 동일하다. 선택 필드 FP만 36건에서 35건으로 바뀌었다. `g-dev-034`의 품목명이 `세제 대용량`으로 확정되어 모델 품목명과 대응됐기 때문이다. 모델을 다시 호출하거나 성능이 개선된 결과는 아니다.

현재 재채점에서 새로 확인 가능한 보조 지표는 선택 필드 누락 15건, 자료형 오류 0건이다.

v2.5의 001~040 정답은 v2.4와 같다. 같은 원시 예측을 v2.5의 001~040에만 다시 채점해도 거래 정확도 11/28, 금액 Exact 22/38, 필수 F1 85.08%, 선택 필드 FP 35건, 누락 15건으로 위 수치와 같다 (2026-09-29 확인). 60건 전체와 섞으면 신규 20건이 생성 실패로 집계되므로, `eval/score.py`는 예측이 없는 ID가 있으면 오류로 중단한다. 일부만 채점할 때는 `--only-predicted`를 쓴다.

## 아직 측정할 수 없는 항목

- 추가 확인 적합성: 백엔드 공통 검증 모듈과 실제 400 응답이 아직 연결되지 않음
- Rule 비교 기준선: 현재 Rule 파서는 mock 골격이어서 비교 대상이 아님
- 5초 전체 처리 보장: SDK 재시도는 끄도록 바꿨으나(`LLM_MAX_RETRIES=0`), SDK timeout은 연결·읽기 단계별 제한이라 서비스 전체 상한은 Rule 전환 래퍼에서 따로 보장해야 함 (BE 협의)
