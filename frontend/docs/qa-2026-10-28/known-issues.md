## P1 수정 완료(로컬) · 운영 배포 대기: 입력과 다른 품목 금액 후보

- 환경: 운영 app.echobill.kr, SM-S931N / Android 17 / 카카오톡 26.8.3. 배포 SHA 미확인.
- 입력: `QA1028에 무 2개 10000원 배추 3개 20000원 합계 40000원 외상`
- 기대: 품목 금액 합계 30,000원과 말한 총액 40,000원의 차이 또는 단가/금액 해석을 사용자에게 확인. 금액을 지어내 합계를 맞추면 안 된다.
- 실제: 미확정 후보 40,000원, 무 2개 20,000원 + 배추 3개 20,000원. 편집 폼에서도 동일. 사용자는 품목을 수정하지 않았다.
- 안전 조치: 후보를 거절했다. 이 40,000원은 장부에 확정하지 않았다.
- 근거: `full-mismatch-two-items.png`, `full-mismatch-accepted-details.png`, `full-mismatch-edit-evidence.png` (이 PC의 QA 캐시).
- 경계 확인: FE `createCandidateDraft`는 응답의 item.amount를 복사하며 초기 표시에서 합계 맞춤을 하지 않는다. 원시 HTTP 응답은 확보하지 않아 서버·AI 원인으로 확정할 수 없다. 후처리의 전역 숫자 검사가 관련 있다는 것은 가설이다.
- 후속 수정: `postprocess.py`의 전역 숫자 집합 검사가 다른 품목의 금액까지 허용하는 빈틈을 재현했다. 같은 잘못된 모델 출력을 주입해 텍스트·음성 API가 수정 전200으로 후보를 저장하는 것을 확인했고, 품목 이름별 명시 금액을 연결하도록 `pp-1.6`에서 보완했다. 프롬프트·모델·API 스키마·DB 변경은 없다.
- 수정 후: 무10000원·배추20000원·말한 총액40000원을 유지해400 AMOUNT_MISMATCH, 후보 저장0건. 사용자가 총액30000원으로 보완한 뒤에만 미확정 후보1건이며 자동 확정하지 않는다.
- 경계: 단가·정정·중복/부분 일치 품목명 등 연결이 모호하면 이번 복원을 적용하지 않는다. 운영 모델 원시 응답은 확보하지 못했으므로 모델의 최초 오해 자체를 제거했다고 주장하지 않는다.
- 검증: 새 회귀19개(수정 전 재현5개 실패), BE2853개 통과(4skip/3xfail), FE303개·lint/build, Golden Dev 회귀4트랙·생성물 일치, Golden 밖8개 직접 대조. 기준선/Golden Test/프롬프트 튜닝 없음.
- 역할 밖 범위: 사용자 중요결함 수정 요청에 따라 BE 후처리1곳과 운영 추적맵2곳만 좁게 수정했다. AI 김수경·BE 최병철 코드 리뷰와 PM 최승현의 운영 반영 판정은 필요하다. 아직 푸시/PR/배포/팀 전송하지 않았다.

## 인식·시간 관찰

- `무` → `모`, `외상` → `매장` 인식 사례. 후자는 진행 중 추가 발화가 섞여 정확도 표본에서 제외했다. 자동으로 원하는 품목·결제 상태로 바꾸지 않았다.
- `모 2개 만원, 외상` 전사 뒤 총액 재질문이 나왔다. 원문에 금액이 있으므로 STT 이후 해석 경계도 확인할 필요가 있다. 장부에 저장하지 않았다.
- 10/29 한 짧은 발화에 사용자 체감 5초 초과 의심. 후속 보완 사례 UI 전환 실측은 3.204–4.500초였다. 같은 측정이나 p95로 합치지 않는다.
- 실제 무음 30초 자동 전송은 연결 실패 안내와 재시도 보관 화면으로 끝났다. 운영 health는 별도 PC 요청에서 200. 원시 네트워크 오류 원인은 미확인.
- 음성 보관 시트와 네트워크 안내가 동시에 남을 때 실제 화면과 접근성 덤프의 최상단이 달랐다. 화면의 X로 정리할 수 있었으나 TalkBack 동작은 확인하지 않았다. 이번 RecordPage 이탈 확인창 겹침 수정과 별도인 추가 접근성 확인 항목이다.
