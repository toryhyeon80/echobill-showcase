## 재채점 방법

- **API 호출 없음.** 저장된 예측(원 출력)에 `eval/score.py --postprocess --attach-validation`을 적용 → `*.rescored-v1.3.summary.json` (27개, 원본 predictions·summary 불변)
- 순서는 운영과 같이 **후처리 → 검증**. 검증은 `eval/validation_bridge.py`가 BE `validate_candidate`를 `/parse`와 같은 방식으로 호출(거래처 수는 운영 Rule 함수, 실행 당시 정규화 설정 그대로)
- 후처리 = **pp-1.3** (#44 머지 후 main 병합). 정규화 off 실행(ko-off·p0-off)은 후처리가 적용되지 않음(운영과 같음, pp-1.2/1.3 구분 없음)
- 채점 v1.3 (10/6 보완): 적합 = HTTP 400 + `error_code` 일치 + `problem_fields`가 `required_clarifications`와 집합 일치 + **`partial_candidate`에 지어낸 필수 값 없음**(선택 필드 제외). **정상 건이 400이면 거래 오답**
- 10/5에 만든 27개는 보완 전 규칙이라 지우고 같은 이름으로 다시 만들었다(PR 미머지라 섞이지 않게)
- 각 칸은 3회(r1·r2·r3) 값. pp-1.2 값은 비교용 숫자만 적고 결과 파일은 만들지 않았다
